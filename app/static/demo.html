Invoice Extraction Pipeline
API docs Source on GitHub

The model reads the invoice. Code checks every number.

Gemini turns an invoice (PDF or photo) into structured data that must fit a strict schema. Then plain code with no AI re-does the math: line totals, subtotal, tax rows, the total, dates, the vendor's tax-ID check digit and duplicates. Only an invoice where everything adds up is approved automatically; anything else goes to a human, who can correct it with a full audit trail.

Invoice PDF / image→ Gemini structured output→ Schema validation→ Checks in code→ Approved or needs review
Measured, not claimed: on 41 labeled invoices (31 synthetic, 10 real Portuguese receipts) the checks flagged 100% of the planted mistakes, and flash-lite read 99.2% of fields right. One real receipt was wrongly auto-approved (a vendor name read as trading + legal name combined). Details and the full eval are in the README. Everything you do here stays in your own sandbox and is deleted nightly.
